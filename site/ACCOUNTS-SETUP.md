# Подключение кабинета LUSAR

Состояние: кабинет реализован в коде; внешний вход ещё не активирован. Google OAuth, отправка писем и реальная регистрация требуют настройки владельцем сервисов. До этого сайт показывает «Вход пока не подключён. Страница в разработке». Гостевое оформление работает отдельно.

## Выбранный способ

Auth0 Universal Login обслуживает Google, регистрацию по email, подтверждение адреса и восстановление пароля. LUSAR принимает проверенный результат входа и создаёт собственную серверную сессию. Пароли клиентов не проходят через сервер или базу LUSAR. Auth0 — отдельный сервис; аккаунт и приложение ещё нужно создать. Тариф и лимиты выбираются при регистрации, никаких платных услуг этим обновлением не подключено.

Создавайте сервисы на рабочую почту компании. У владельца должен быть собственный доступ администратора Auth0 и Google Cloud. Передача проекта выполняется через доступы владельца, а секреты можно заменить; отправлять их в чат не нужно.

## 1. Приложение Auth0

1. В [Auth0 Dashboard](https://manage.auth0.com/) создайте tenant LUSAR и приложение **Regular Web Application**, например `LUSAR staging`.
2. В Settings задайте:

| Настройка | Значение для действующего стенда |
| --- | --- |
| Allowed Callback URLs | `https://lusar-staging.onrender.com/auth/callback` |
| Allowed Logout URLs | `https://lusar-staging.onrender.com/account/sign-in` |
| Allowed Web Origins | `https://lusar-staging.onrender.com` |
| Token Endpoint Authentication Method | `POST` / `client_secret_post` |
| Grant Types | `Authorization Code` |
| ID Token Signature Algorithm | `RS256` |

3. Включите **Universal Login**. В Tenant Settings включите языки `ru`, `hy`, `en`, основной — русский. Сайт передаёт выбранный язык через `ui_locales`. Укажите название LUSAR, логотип и графитово-чёрные цвета с бронзовым акцентом.
4. В Authentication → Database включите `Username-Password-Authentication` для этого приложения, разрешите регистрацию и восстановление пароля. Включите отправку email подтверждения, защиту от перебора и обнаружение скомпрометированных паролей в доступных настройках tenant. LUSAR принимает email только после подтверждения (`email_verified=true`).

Ссылки: [редирект после входа](https://auth0.com/docs/authenticate/login/redirect-users-after-login), [выход](https://auth0.com/docs/authenticate/login/logout/redirect-users-after-logout), [языки Universal Login](https://auth0.com/docs/customize/internationalization-and-localization/universal-login-internationalization).

## 2. Google

1. Создайте отдельный проект LUSAR в [Google Cloud](https://console.cloud.google.com/). Настройте Google Auth Platform: название, рабочий контакт и экран согласия. Для тестирования добавьте тестовые email.
2. Создайте OAuth Client типа **Web application**.
3. В Google укажите origin `https://ВАШ-ДОМЕН-AUTH0` и redirect URI `https://ВАШ-ДОМЕН-AUTH0/login/callback`. Здесь нужен домен Auth0 из его Settings, а не `/auth/callback` сайта LUSAR.
4. В Auth0 → Authentication → Social настройте Google connection с именем **`google-oauth2`**. Вставьте Google Client ID и Client Secret непосредственно в Auth0, включите connection для приложения LUSAR. Нужны только профиль и email, доступ к Google Drive/почте не требуется.
5. Проверьте connection через **Try Connection**, затем вход с сайта. Перед открытым запуском завершите публикацию экрана согласия Google и необходимые проверки, которые покажет Google Cloud. Developer keys Auth0 оставляйте только для тестов.

[Официальная инструкция Google connection](https://auth0.com/docs/authenticate/identity-providers/social-identity-providers/google).

## 3. Письма

В Auth0 → Branding → Email Provider подключите рабочий почтовый сервис через поддерживаемого провайдера или SMTP. Для полноценного запуска нужны подтверждённый отправитель на домене компании и DNS-записи, которые выдаст почтовый сервис. Потребуются доступ к DNS, адрес отправителя и реквизиты сервиса. Их вводят в Auth0, не в репозиторий.

Включите и оформите шаблоны **Verification Email** и **Change Password** от имени LUSAR. Проверьте доставку в обычную почту и спам. Встроенная тестовая отправка Auth0 не заменяет почту для рабочего запуска. Восстановление на сайте открывает страницу входа с повторным вводом данных, где клиент выбирает восстановление пароля.

[Настройка почтового провайдера Auth0](https://auth0.com/docs/customize/email/smtp-email-providers).

## 4. Render

В **lusar-staging → Environment → Edit** добавьте:

| Переменная | Что вставить |
| --- | --- |
| `LUSAR_AUTH0_DOMAIN` | Domain из Auth0, например `lusar.eu.auth0.com`, без пути |
| `LUSAR_AUTH0_CLIENT_ID` | Client ID приложения **Auth0**, не Google |
| `LUSAR_AUTH0_CLIENT_SECRET` | Client Secret приложения **Auth0**, не Google |
| `LUSAR_PUBLIC_ORIGIN` | `https://lusar-staging.onrender.com` |

Последняя переменная необязательна на Render: по умолчанию используется `RENDER_EXTERNAL_URL`. Origin всегда без завершающего слеша и пути. Сохраните и перезапустите сервис. Существующие переменные базы, Telegram, AI и статистики оставьте как настроены. Google secret и SMTP-реквизиты нужны Auth0; на Render их добавлять не требуется.

`/healthz` покажет `accounts.configured: true`, когда обязательные параметры заполнены. Это подтверждает наличие конфигурации, но не доступность Google/почты и не успешный вход. Реальную проверку нужно пройти отдельно. Не снимайте пароль и `noindex` со стенда ради настройки авторизации.

## 5. Проверка после подключения

На стенде используйте тестовые данные:

- Создайте аккаунт по email. До подтверждения письмом кабинет не должен открываться; после подтверждения повторный вход должен работать.
- Войдите через Google; проверьте RU / HY / EN, восстановление пароля и выход. После выхода защищённые API должны вернуть 401.
- Добавьте товар гостем, войдите, сохраните адрес и оформите заявку. Проверьте номер в истории клиента и панели менеджера.
- В другом браузере войдите тем же способом: проверьте корзину, избранное, адрес и историю. Другой клиент не должен видеть эти данные.
- Проверьте первую скидку 10%, её резервирование текущей заявкой, освобождение после отмены и пересчёт накоплений после оплаты/выполнения и возврата.

Google и email/password — разные идентификаторы провайдера. Аккаунты с одинаковым email намеренно не объединяются автоматически: это требует отдельного подтверждённого сценария связывания. Старые гостевые заказы по совпадению телефона/email к аккаунту не привязываются. Права сотрудников и администратора этим входом не выдаются.

## Что уже реализовано и проверено локально

- Профиль, до десяти адресов с основным адресом, собственная история заявок с пагинацией, накопительная скидка, первый заказ.
- Перенос гостевой корзины/избранного после входа и хранение в аккаунте. При конфликте изменений с другого устройства сервер возвращает 409; сайт предлагает обновить страницу, не перезаписывая серверную версию молча.
- Накопления бессрочные: 0% до 50 000 ֏; 3% от 50 000; 5% от 100 000; 7% от 300 000; 10% от 500 000; 15% от 1 000 000. Учитываются выполненные оплаченные заказы после скидок и возвратов.
- Первая скидка 10% применяется отдельно. Личная скидка совместима с одним промокодом; фиксированный промокод ограничен 20% суммы после личной скидки. Суммы считает сервер.
- OIDC Authorization Code + PKCE, одноразовые state/nonce, проверка подписи и claims ID token, подтверждённый email. Сессии на семь дней: случайный токен в Secure/HttpOnly/SameSite cookie; в базе только его хеш. Изменения требуют Origin и CSRF. Токены Google/Auth0 не сохраняются в браузере или базе. Вход ограничен по частоте.
- Миграция PostgreSQL `002_accounts.sql` добавляет таблицы аккаунтов и владельца заказа. Существующие заявки сохраняются.

Локальные тесты используют изолированную базу и локально подписанные тестовые удостоверения; внешние Google, Auth0 и почта ими не проверяются:

```powershell
python -B site/check_accounts.py
python -B site/check_account_ui.py --browser 'ПОЛНЫЙ-ПУТЬ-К-CHROME.EXE'
```

Для локального тестирования установите `site/requirements.txt`. Тесты не отправляют настоящие письма, уведомления Telegram или запросы AI.

Для будущего рабочего домена создайте отдельное приложение/секрет Auth0 и отдельные разрешённые адреса рабочего сайта. Перед запуском перенесите настройки origin, подтвердите почту, проверьте резервное копирование базы и роли сотрудников. Рабочий домен этим обновлением не переключается.
